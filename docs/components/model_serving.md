# Model Serving & Deployment

The deployment module handles the lifecycle of transitioning registered models into live, queryable API endpoints.

## Deployment Architecture
Deployments are initiated entirely through the Python SDK; the web dashboard is strictly read-only. 

- **Triggers:** A deployment request triggers a message queue.
- **Execution:** A separate Python Deployment Service consumes the task.
- **Environments:** Models can be deployed using prebuilt images (for `.pickle` or `.keras` files) or custom images defined in the Artifact Registry.
- **Monitoring:** The status of the deployment (and deletion) is monitored by the deployment service via polling. *(Note: While polling works for the MVP, it is flagged as an area for future architectural improvement).*

## Schema Validation
When deploying a model, an input and output schema must be defined. The SDK utilizes **Pydantic** to define these schemas.

### The Pydantic to JSON Schema Pipeline
The backend relies heavily on Pydantic's `model_json_schema()` method. While the resulting output is highly complex, it serves critical architectural purposes:

1. **Gateway Validation (Go):** The JSON schema generated by Pydantic is a mathematically formal OpenAPI/JSON Schema Core specification. The Go API Gateway ingests this exact schema and utilizes standard libraries (like `github.com/santhosh-tekuri/jsonschema/v5`) to rigorously validate incoming inference requests at the edge.
2. **React UI Presentation:** The frontend does not need to parse or resolve references within this complex schema. The React dashboard simply stringifies the raw JSON schema for display purposes, looking technical and professional with zero frontend processing effort.
