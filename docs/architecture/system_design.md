# System Design

The platform operates out of a monorepo and is composed of several decoupled services and components working together. 

## Control Plane API (FastAPI)
The Control Plane is a monolithic application acting as the sole entry point for platform administration. It is strictly structured using an **Onion Architecture** containing four isolated layers:

1. **Core:** The purest layer. It contains domain entities and interfaces (ports). The only external dependency here is `pydantic`, utilized as a robust replacement for native Python dataclasses.
2. **Application (Services):** Contains the business logic. It utilizes ports and domain entities from the core to construct workflows. It defines its own interfaces for better testability and mocking.
3. **Infrastructure (Adapters):** Implements the ports defined in the core. It reuses domain entities and contains all external interactions, ORMs, and database queries.
4. **Presentation (API Routes):** Depends on all the underlying layers. This layer exposes the FastAPI routes and houses the Dependency Injection (DI) mechanism. The `dependencies.py` file resolves and provides instances (like repositories) to the endpoints.

> **Note:** Primary keys are exclusively generated by the Control Plane API (FastAPI) to guarantee integrity. The client (SDK) never generates IDs.

## The Edge Gateway Pattern
Initially, the system considered using a sidecar pattern (injecting a Go API Gateway alongside every model container). However, due to severe networking complexities within Kubernetes (CORS, internal IP routing), the architecture utilizes the **Edge Gateway Pattern**.

- **API Gateway (Go):** A single Go application runs locally adjacent to the FastAPI app. All UI and external model traffic routes through this gateway (`localhost:8080`).
- **Functionality:** It intercepts requests to models, validates authentication (JWT), logs the requests and responses to PostgreSQL for observability, and proxies the traffic directly to the Minikube IP.
- **Benefits:** Requires zero complex Kubernetes networking configurations, utilizes a single database connection pool, and simplifies the deployment model.

## Secondary Components

### Deployment Service (Python)
An event-driven service responsible for actualizing models. It receives tasks from the Control Plane, pulls the specified image (default prebuilt images for `.pkl`/`.keras` or custom images), configures it, and deploys it to the cluster. It updates deployment statuses via polling.

### Python SDK
The primary interface for data scientists. It interacts with the Control Plane for all platform management tasks, dataset handling, and model deployments.

### Web App Dashboard (React + Tailwind CSS)
A purely read-only dashboard designed for observability. It allows users to view system states, experiments, and model performance. Data processing is kept minimal on the frontend; the backend structures data specifically for easy UI rendering.

## Core Infrastructure
- **PostgreSQL:** The central database for all structured data and metadata, as well as message brokering.
- **Grafana:** Embedded monitoring and plotting.
- **MinIO:** S3-compatible object storage for datasets and model artifacts.
- **Gitea:** Manages artifact registries and Git repositories.
- **Kubernetes (Minikube):** The underlying container orchestration platform.
